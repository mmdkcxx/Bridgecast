# Product

Name: Bridgecast. Tagline: From slide to screen, live. Brand and voice: `docs/brand/`.

<!-- impeccable:product-schema 1 -->

## Platform

web

(Electron desktop app for Windows; the UI is a web renderer. One operator window plus a borderless fullscreen output window on a second display.)

## Users

- Event operators who run the slides at a live event: both professional AV technicians or event vendors (multimedia/LED crews handling many events and clients) and non-specialist client staff or committee members running their own internal events. The UI must be safe for the less experienced operator without slowing down the expert.
- Their job: keep the right slide on the projector or LED screen for every speaker in an event, often under time pressure, in a dark venue, while speakers may drive slides themselves with a presentation clicker.
- Without this product they switch between PowerPoint windows so the screen capture or projector shows the right deck (spec: docs/superpowers/specs/2026-10-06-ppt-share-design.md).

## Product Purpose

- Keep every deck of an event in one library and show the live slide ("Program") fullscreen on a second display over HDMI (Windows Extend mode), controlled from one operator window.
- Success: the audience never sees desktop, wrong slides, black flashes, or the next speaker's deck by accident; the operator always knows what is on air and what comes next.

## Positioning

- Not "PowerPoint on a second screen": PowerPoint (or pdf.js) is used only at import time to convert slides to images; during the show the app renders Program itself and behaves like a broadcast program bus: LIVE / FROZEN / BLACK / KV / STANDBY tally, Cut or Fade, Freeze that holds the output while the operator previews other slides, a key visual hold image, and no separate Preview bus (Next/Prev change Program directly).
- Runs offline, with one exception: a web deck (below) needs the network while it loads and plays. The output never moves onto the operator's own display.

## Operating Context

- Workflow: create an event (starts empty), import .pptx/.ppt/.pdf by button or drag and drop (per-file progress), reorder and rename decks, set an optional KV (key visual) image per event, connect HDMI and choose the target display, then run the show with keys or clicker.
- Controls: Space / Right / Down / PageDown = Next, Left / Up / PageUp = Prev (Down and Up are for clickers that send arrow keys), F = Freeze, B or "." = Black, K = KV, N = Next section, Shift+N = Prev section, D = Next deck, Shift+D = Prev deck (D / Shift+D work for every deck; on a live web page Next/Prev go to the page, so the keys that leave it are D, Shift+D, N, Shift+N, B and K). Keys work only while the operator window has focus, with one exception: Settings > "Clicker in the background" (off by default, applies at once, spec docs/superpowers/specs/2026-11-26-background-clicker-design.md) makes the clicker keys run Next / Prev while no Bridgecast window has focus (Settings > "Clicker keys": PageDown / PageUp by default, or Right / Left arrows for clickers such as Perfect Cue), so a speaker's clicker keeps working while the operator replies to messages or prepares files. The two chosen keys then come from every keyboard on the PC and do not reach other apps; Home, the tour and Interact still pause them; Up / Down arrows are never taken in the background.
- Auto advance to the next deck is off by default so a clicker stops at the end of the live deck; it is a saved switch.
- Freeze holds the output while the operator moves a preview; unfreeze keeps the held slide live and returns the position to it (changed 2026-10-08 at the user's request; before, unfreeze took the preview live).
- HDMI can disappear mid-show: the output hides and returns when the same display reconnects.
- Environment: Windows 11, PowerPoint installed for PPT/PPTX import (COM), offline, NSIS installer. Field checklist: docs/test-checklist.md.

## Capabilities and Constraints

- Input: .pptx, .ppt, .pdf (macOS: a .pptx/.ppt is first converted to PDF in main with Microsoft PowerPoint (exports the PDF itself, added 2026-11-26), else Keynote, else LibreOffice, then imported as a PDF deck: Vector only, no animations, never Native; the PowerPoint file is kept as original.*; the first import asks for the Automation permission for PowerPoint or Keynote; not verified on a real Mac), always also converted to PNG slides (1920 px wide) with speaker notes; the PNG is the fallback. Each deck plays as Native (PowerPoint decks: the real slide show in a window, captured into every output, so animations, video and sound inside slides play; Next walks click steps; Windows with PowerPoint only), Vector (PDF and static decks: drawn sharp from the PDF) or Still images. Chips: Native · Opening / Ready / Fallback, Vector, Still images. If PowerPoint crashes or hangs while live, the output shows the PNG of the same slide (never black, never the desktop) with "PowerPoint is not responding..."; the slide show returns to native once PowerPoint is back (Resume PowerPoint when its session is already open). Edit in PowerPoint (deck menu) opens a working copy and re-exports on every save; a save while the deck is live waits ("Changes apply when this deck leaves air.") until it leaves air or Apply now; Revert returns to the imported file, and original.* is never modified. Spec: docs/superpowers/specs/2026-10-27-native-slideshow-design.md. Spec: docs/superpowers/specs/2026-10-27-libreoffice-linux-design.md; not yet verified end to end, see docs/test-checklist.md, "Putar PPT di Linux (LibreOffice)". Linux (X11, or Wayland through Xwayland) uses the same Native / Vector / Still images modes through LibreOffice Impress (bridge `native/lo-bridge`, a private PulseAudio sink `pptshare_lo` for its sound, Edit in LibreOffice with a save warning); on Wayland without Xwayland the app says LibreOffice slide shows need X11 and decks play Vector or Still images; a video inside a slide plays its sound but its picture is not captured. - One output (HDMI, second display) with the Program content. Network output: OMT and NDI (see below). Removed or out of scope: a second output with different content, transcript or speech-to-text, timer, nested sections, remote control from other devices.
- Sections (2026-10-12): optional dividers in the deck list (Add section, rename, move, remove; the deck menu has Add section above). A section is a boundary for auto advance: the clicker stops at its last slide and Up next shows "End of section". N / Shift+N jump to the next / previous section and go live at once (while frozen they only move the preview). Spec: docs/superpowers/specs/2026-10-12-sections-design.md.
  - Events with sections should not be edited in a build older than 2026-10-12: it does not shift section positions when decks move or are removed, so section boundaries drift (no deck is lost).
- Video slides (shipped 2026-10-09): an animated page imported as a folder of `page-NN.png` + `page-NN.mp4` (drop the folder on the app) plays once when it goes live and holds its last frame. Black or KV off shows the end frame again. A single MP4, M4V, WebM, MOV or MKV file can also be added directly (Add files, drag and drop, or New event): one file becomes one deck with one video slide, named after the file, with a poster taken from a frame near the start. Only H.264 MP4 or WebM play (MOV/MKV depend on their codec); anything else is refused at import with a message instead of failing on air. Audio plays on the HDMI output, with an audio device choice and Mute all. Video slides carry a play mark in the strip and in Up next. Canva import comes next. Spec: docs/superpowers/specs/2026-10-09-video-slides-design.md; direct import: docs/superpowers/specs/2026-11-17-video-file-import-design.md.
- Image slides: a PNG, JPG, WebP, GIF, BMP or AVIF file can be added the same way; one image becomes one deck with one slide (converted to PNG on import, animated images keep their first frame).
- Canvas (2026-10-27): the output has a canvas size, default 1920×1080 per machine (header Canvas chip popover) with an optional override per event (Controls > Deck settings, "Canvas for this event…"). Presets 1920×1080, 3840×2160 and 1280×720, Match HDMI display, or Custom; each side is 320–7680 px and rounded down to an even number, at most 3840×2160 pixels in total (so 7680×1080 is allowed). Changing it while a slide is on air asks for confirmation. Slides are drawn into the canvas and the canvas is scaled to the HDMI window. Spec: docs/superpowers/specs/2026-10-27-canvas-audio-levels-design.md.
  - New event (2026-11-17, asked for by the user so an event is "ready when it is used"): the dialog has a Canvas list (Default, the presets, Match HDMI display, Custom size) and three Outputs switches (HDMI, OMT, NDI) that start from what is on now on this PC. The canvas is the event's override. The outputs are saved per event (`EventMeta.outputs`) and applied to this PC's output settings when the event becomes the output's event (the air event): at once when nothing else owns the output, otherwise at its first take, the same rule as the canvas. A switch the operator flips in the Output panel is remembered by the event that owns the output. Events without saved outputs (made before this, or through the API without options) leave the outputs as they are. HDMI that cannot turn on (no second display) stays off and the event keeps its wish. Automated: `npm run test:e2e:new-event` (fake OMT/NDI); HDMI switching by an event is not verified with a real second display.
- Fit, Fill, Stretch (2026-10-27): each deck chooses (deck menu, "Display mode") how its slides fill the canvas: Fit (whole slide, black bars), Fill (crops to cover) or Stretch (distorted). Default Fit. The KV is always Fit and strip thumbnails stay Fit. Changing it for the live deck updates the output at once and never replays a video slide.
- Deck and master volume (2026-10-27): every deck has a volume (0–100) and a mute (deck menu, "Sound…"), and the Sound chip popover in the header has a master volume next to Mute all. Sound is the deck volume times the master volume, 0 when either is muted; a change is smooth and does not replay the live video. The output's sound goes through the Web Audio API; if that is unavailable it falls back to the video's own volume. Spec: docs/superpowers/specs/2026-10-27-canvas-audio-levels-design.md.
  - Settings, events and decks saved with these fields should not be edited in a build older than 2026-10-27: it does not know the canvas, Fit, deck volume or master volume, so it drops them the next time it saves and everything returns to 1920×1080, Fit and full volume (no deck or slide is lost).
- OMT output (2026-10-27): Program, with its sound, can also be sent over the LAN with Open Media Transport so vMix 29+ and OBS 31+ (with the OMT plugin) can take it as a source (Resolume: best effort, unverified). The libraries libomt and libvmx are MIT-licensed and ship in the installer. The picture size is the canvas size; frame rate 30 (default) or 60; the source name is shown to receivers as "HOSTNAME (NAME)". OMT works with or without HDMI: it has its own offscreen renderer. Changing the canvas, frame rate or name restarts the sender, so receivers may lose the picture for a moment (the real gap is still to be measured). Sound route (Sound chip popover): Local device, OMT or Both. Rule: exactly one window plays the sound on this PC (the HDMI window while it shows, otherwise the OMT window while OMT runs); route OMT silences this PC, Local keeps it off the network. Windows asks to allow Bridgecast through the firewall the first time OMT is switched on. Spec: docs/superpowers/specs/2026-10-27-omt-output-design.md; spike numbers: docs/superpowers/notes/omt-spike.md.
- NDI output (removed 2026-10-08 for SDK licensing; re-added 2026-10-27): the same Program, with its sound, can also be sent as an NDI source, alone or together with OMT, so vMix, OBS (DistroAV) and NDI Monitor can take it (not yet verified on Windows or with a real receiver; see docs/test-checklist.md). The NDI Runtime is never bundled with Bridgecast: the Windows installer downloads it from ndi.video when it is missing (intended: signature checked, and if the download fails the install continues without NDI and the app says the runtime is not installed; not yet verified on Windows, see docs/test-checklist.md). OMT and NDI share one offscreen renderer and one frame clock. The frame rate setting (30 or 60, stored as omt.fps) applies to every network protocol, so changing it restarts both senders and receivers may lose the picture for a moment. The sound route labels are Local device, Network and Both; Network and Both send the sound to every network protocol that is on, and the rule of exactly one window playing on this PC is unchanged. Spec: docs/superpowers/specs/2026-10-27-omt-output-design.md; plan: docs/superpowers/plans/2026-10-27-ndi-output.md.
- Canva import (planned 2026-10-09, cancelled 2026-10-31 by the user): no Canva link import, OAuth or Cloudflare Worker will be built. Canva decks are played through the in-app browser instead (web decks, below). The old spec and plan stay in docs/superpowers/ for reference only.
- Web decks (2026-10-27, code done, not yet verified on Windows or with real Canva): a deck can be a web page (Canva in present mode, YouTube, any https page) added with Add web page. Each web deck is one hidden page whose picture and sound are captured into the HDMI output, the OMT/NDI output and the operator monitor, so every output shows the same page position. Chips: Loading, Ready, Error, HOLD. A page can only go on air once it is Ready (the ready gate: a captured frame has arrived); "Web page not ready" otherwise. Prepare window (deck menu, Prepare…): the operator clicks and types in the page (login, Present, close pop-ups) while it is not on air or while the output is frozen; while it is live and not frozen the window refuses clicks and typing unless Interact is on ("On air. Turn on Interact to click and type in the page.")). The Prepare window is a small browser: Back, Forward, Reload (Stop while loading), Home (the deck address), an address field and a More menu. View: Fit draws the whole page in the window, 100% draws one page pixel per screen pixel and pans by drag, wheel, arrow keys or a mini-map (the Map button hides it). Interact (on by default for a page that is not on air; on air it is turned on by a press, and it goes off when the deck goes live, leaves air, or the Prepare window closes) switches between looking and clicking or typing in the page. On air with Interact on, the clicks reach the audience: the banner says so, and Esc turns Interact off. The operator monitor has the same Interact switch on the live page (Program, next to the tally), with a banner "INTERACTING: your clicks reach the audience. Esc to stop."; Esc sends one Escape to the page and releases the keyboard, F6 moves to the address field. The page zoom (More menu, 50% to 200%) changes the page itself, so every output shows it; it is saved per deck, refused while the page is live and not frozen, and labelled as changing the output. A tally frame and the status line say Not on air, Frozen or Live. The window remembers its size and position per PC. Known limit: the page's native pop-up lists (a <select>, date pickers, autofill) are not drawn in the preview; use the keyboard (focus the field, then the arrow keys) instead. Live, Next/Prev (and a clicker) are forwarded to the page as one arrow key per press and never move the deck position, so leaving a web page is always deliberate: D / Shift+D (or picking another deck). The page blocks ads and trackers (Ghostery lists, cached on disk, best effort and never blocks the show; `PPT_ADBLOCK=0` turns it off). The page is a normal browser profile for the whole machine (one saved login for all web decks; the user agent is Chrome's, without the Electron and app tokens); "Sign out of all websites" (Prepare, More menu) clears it and is refused while a web page is on air. A live page cannot open pop-ups or ask for the camera, microphone, location or notifications; downloads are cancelled; only http and https addresses load.
  - The only part of a show that needs the network. Guards: the ready gate before the take, and HOLD while live. HOLD (button state "Resume web", chip HOLD) starts, by events only (no connection polling), on a failed main-frame load, a crashed page, an unresponsive page (Chromium's own hang detection first, then 5 s more), or an ended capture track. Reload, Back, Forward or Edit URL on the live page (not frozen) go to HOLD first and only then navigate, so the audience never sees the page reload or an error page. The output then keeps the last good frame (a copy of the last frame shown on top of the paused stream, also when the capture track ends; verified on Linux/xvfb only), and the operator decides: take another deck, K or B, or Resume web once the page is Ready again. HOLD never ends by itself, and K or B off is refused while the page is not Ready, so a failed page never comes back on air. A page that is already loaded keeps showing as is when the internet drops; HOLD comes with the next failed load (for example Reload).
  - One event is on air. Tabs and Home never change the output, including the canvas and the KV: the on-air event's tab cannot be closed (no ×, Delete is ignored) and is reopened if it goes missing, and switching tabs or opening Home leaves the output, the canvas and the take as they are. The air event changes only when a slide, KV or web page of another event is taken. Off air (Home banner and, on the console, the header left of the Light/Dark switch (moved out of Controls 2026-11-17), after a confirm: "Take <event> off air? The output goes to STANDBY.") is the only way, besides taking another event's slide, KV or Black, to change the air state from Home or the tabs; it returns the output to STANDBY, never Black, and keeps the event's position (decided by the user, 2026-11-06). Since 2026-11-17 the app always starts on Home with no event tab open (tabs are not brought back from the last run), and the Home button only opens Home: it does not switch back to the console (a tab, an event card or "Back to console" does). Recent uses the last-opened time of each event.
  - Sound: Settings > Sound holds the audio device ("Default (Windows)" or a named device) and Sound to (Local device, Network, Both). The transport sound button mutes the output sound (HDMI, native PowerPoint, web decks and the network sound). Windows device lists, unplug and default-follow behavior are unverified; see docs/test-checklist.md.
  - Switching to another event does not change the output: a live web page stays on air with its host window until a slide of another deck is taken.
  - Limits: a captured page has no focus (`document.hasFocus()` is false), Windows may occlude hidden windows (the app turns the CalculateNativeWinOcclusion feature off), Google sign-in may refuse an embedded browser (use the Canva email sign-in), DRM video does not play, a Prepare window only works for decks of the open event, and on Windows a page window can be clamped below the canvas size (the operator then sees a warning above Program). Verified on Linux/xvfb only so far (automated: `npm run test:e2e:web`); the Windows and real-Canva checks are in docs/test-checklist.md. Spec: docs/superpowers/specs/2026-10-27-web-source-design.md; spike: docs/superpowers/notes/web-source-spike.md.

A header chip, a popover under the header and a Settings > About block announce the version and its plain release notes. Since 2026-11-17 no operator action is needed: the update downloads by itself while nothing is on air (a version found during a show waits until the Program is off air; the operator may still click Download) and installs when Bridgecast is closed with nothing on air. ## Product Principles

1. What is on air is never ambiguous: the operator can always tell what the audience sees and what Next will do.
2. Mistakes must not reach the screen: guard rails over speed (auto advance off by default, freeze as preview, no black frames, output never on the operator's display).
3. Keyboard and clicker first, mouse second; nothing during a show requires precise mouse work.
4. Works in a dark room under pressure for both an expert technician and a first-time committee member.
5. Offline and self-contained: a show never depends on the network, except a web deck, which is guarded by the ready gate before it goes on air and by HOLD while it is live.

## Accessibility & Inclusion

- Used in dark venues: both themes keep high-contrast text (the default follows the OS, so a venue PC may need dark set by hand), state shown by text and shape, not colour alone (red is reserved for on-air tallies, amber for "next").
- Fully operable by keyboard and presentation clicker; target WCAG 2.1 AA for the operator window.
